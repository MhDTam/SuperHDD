# Hardware and feature audit — 2026-10-18

The SSD-file cache algorithm works through its own API. It is not a transparent Windows accelerator. The experimental storage filter remains unsigned, uninstalled and gated. No driver or partition was installed/modified during this audit.

## Method

Source: new 1 GiB disposable file on each real HDD (E: WD10EURX and D: Hitachi). Cache: separate file on M: Samsung 980 PRO NVMe. Two reservations total 24999886848 bytes (<25 decimal GB), including approximately 12.5 GB for each source. This is a temporary test allocation, not an active system cache.

Reads bypass the Windows file-data cache using FILE_FLAG_NO_BUFFERING on source and backing, with 4096-byte aligned buffers. QD1, 1536 identical random offsets over a 1 GiB address range, 96 MiB unique hot data, three rounds. SHA-256 read-stream digests match. Drive firmware/controller caches and background system activity remain present; this is not a controlled laboratory or game-loading test. Reported throughput is the median of three rounds and includes digest computation.

## Cold and sequential behavior

- E: cold-fill random 64 KiB: 3.16 MiB/s. Sequential 512 MiB: HDD 82.71, cache bypass 98.26 MiB/s. 64 KiB p95 latency: 26.47 -> 0.16 ms.
- D: cold-fill random 64 KiB: 5.24 MiB/s. Sequential 512 MiB: HDD 95.78, cache bypass 95.27 MiB/s. 64 KiB p95 latency: 17.27 -> 0.20 ms.

Cold reads do not become SSD-speed reads. Sequential results can vary with drive/controller caches and background activity; the E: second scan is faster, while D: is essentially unchanged. No general sequential multiplier is claimed.

## Verified features and boundaries

- Both HDDs: byte-identical reads, warm source-API avoidance, pause/resume, aligned-write invalidation, corrupt-SSD fallback, eviction, resize, clear, sequential-bypass and game-admission policy controls passed. Game-admission is an algorithm policy, not actual game acceleration.
- 25 Rust automated tests passed: 11 cache tests, 11 platform tests, 3 download integration tests. The actual HTTP pause/range-resume/integrity/no-overwrite test published a verified 2 MiB file onto E:. Quota rejection and interrupted-manifest recovery passed.
- E: originally disappeared because Windows reports MediaType=Unspecified. Read-only seek/ATA probes could not classify this controller path. Added a conservative manufacturer-model fallback for WD10EURX, with explicit mediaEvidence. A boot/system partition on the same physical disk does not exclude the separate E: data partition.
- Downloads is optional: direct links only, SSD staging then hash-verified HDD delivery. It neither captures browser downloads nor changes internet bandwidth. Worker lifetime follows the desktop process; restart recovers interrupted jobs paused.
- PrimoCache UI/desktop command removed. Its local files remain untouched. No active vendor driver was found; its CLI requires OS elevation. It is a development reference, not this app's advertised engine.
- Simplified primary navigation; Downloads/Gaming/Diagnostics are under More tools. No fake cache metrics on Home. Saved benchmarks appear on Performance with explicit scope and date. E:/M: are defaults when no saved selection exists; selections persist.
- Transparent I/O, game loading, persistence across boots, kernel runtime, automatic updates/startup and service installation remain unavailable/unverified. They were not represented as passed.
